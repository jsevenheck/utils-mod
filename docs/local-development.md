# Local Development (VS Code)

How to build, run, and debug Compass HUD locally.

## Prerequisites

- JDK 25 (the project targets `options.release = 25`; a matching JDK must be on your machine or configured in your IDE).
- VS Code with the **Extension Pack for Java** (`vscjava.vscode-java-pack`) installed, so the Java debugger and Gradle integration work.
- No Minecraft account/launcher needed — Fabric Loom's dev environment runs an offline session automatically.

## Running the game

### Option A — terminal (simplest)

From the workspace root:

```bash
./gradlew.bat runClient   # Windows
./gradlew runClient       # macOS/Linux
```

This compiles the mod, launches the Minecraft client with Compass HUD loaded, and streams logs to the terminal. First launch downloads Minecraft/Fabric artifacts and can take a few minutes; subsequent launches are fast.

Other useful tasks:

```bash
./gradlew build       # compile + package the mod jar into build/libs/
./gradlew runServer    # launch a dedicated server (for testing src/main-only/common code)
./gradlew clean        # wipe build output
```

### Option B — VS Code Run & Debug panel

Loom can generate VS Code launch configurations:

```bash
./gradlew.bat vscode
```

This writes `.vscode/launch.json` with **"Minecraft Client"** and **"Minecraft Server"** configurations (the file is git-ignored — it contains machine-specific absolute paths, so every clone regenerates it locally). Open the Run & Debug panel (`Ctrl+Shift+D`), pick **Minecraft Client**, and press ▶. Because it's a standard `java` launch config, you can set breakpoints in `CompassHudRenderer.java` (or anywhere else) and they'll be hit normally.

Re-run `./gradlew.bat vscode` any time after a Loom/Gradle upgrade, since the config embeds a path into Loom's cache.

## Iterating on changes

The Fabric dev environment does **not** hot-reload Java changes into a running game. After editing code:

1. Stop the running client (close the window, or stop the debug session).
2. Re-run `./gradlew.bat runClient` (or the VS Code launch config) — Gradle only recompiles what changed, so restarts are fast after the first launch.

## Where things live

- `run/` — the dev environment's working directory: saves, logs (`run/logs/latest.log`), crash reports (`run/crash-reports/`), config. Git-ignored. Delete it to reset your dev world from scratch.
- `build/libs/` — build output (`utils-mod-<version>.jar` + `-sources.jar`). Git-ignored, regenerated by `./gradlew build`.
- `build/reports/problems/problems-report.html` — Gradle's build diagnostics if something looks off.

## IDE source navigation (optional)

Vanilla Minecraft classes (`net.minecraft.*`) aren't readable by default since they ship obfuscated/without sources. To decompile them for IDE navigation (jump-to-definition, hover docs):

```bash
./gradlew.bat genSources                    # decompiles everything (client + common)
./gradlew.bat genClientOnlySources          # client classes only — faster
./gradlew.bat genCommonSources              # common classes only
```

This is a one-time (per Minecraft version) operation and can take a while; you don't need to re-run it unless you bump `minecraft_version` in `gradle.properties`.

## Manual test checklist for the compass

When testing changes to `CompassHudRenderer`, verify:

- Compass appears top-center once you're in a world (not on the title/loading screen).
- Facing N/E/S/W centers the matching letter under the `▲` marker.
- Rotating across 359° → 0° doesn't jump or glitch.
- Looks correct at different GUI scales (`Options → Video Settings → GUI Scale`).
- No console errors/exceptions in `run/logs/latest.log` related to `compass-hud`.
- Waypoint dots (other players) on the compass strip: these only render when there's another real player nearby, so a single-instance dev session shows nothing there by design. To test: pause your `runClient` world and **Open to LAN**, then launch a second client (a second `runClient` run, or a vanilla install/second account) and join `localhost:<port>`. Verify the other player's dot tracks their direction, scrolls with the compass, and shows an up/down arrow when they're above/below your view.
